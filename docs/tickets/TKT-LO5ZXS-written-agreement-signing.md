# TKT-LO5ZXS — Written Agreement signing in the client portal

The authenticated client portal rewrote view/download links from its shared tracker payload but left preview/sign actions on the public tracker. Immigration cases are deliberately excluded there, so both requests returned 404 for signed-in clients with an owned agreement.

The portal now rewrites all document actions and supplies authenticated own-document preview/sign routes. Public Immigration tracker privacy remains enforced, including a fresh check under the signing lock. Sharing, hidden-document rules, acknowledgment and valid signature images are checked. Identified modern engagement drafts remain unavailable until sent or explicitly shared; the separate Documents page also filters draft and hidden metadata from checklist files, request attachments and shared lists. Its checklist falls back to the latest visible file. Legacy issued records continue to work.

The existing issued Education PDF signer is extended and named `IssuedClientAgreement` to own the same guarantees for Written Agreements. It binds signing to the checksum of the viewed PDF, copies the original issued pages and appends a signature confirmation page. This preserves original terms, names, adviser details and fees even for legacy documents without snapshots. Original issued bytes stay private and unchanged. Signed document downloads prefer the signed private PDF over a linked Media Drive original; the original media bytes and attachment lineage remain untouched. The existing UI already submits this checksum and explains the confirmation page.

A shared case lock and database row locks serialize signing with other engagement writers. Checked writes create unique PDF/signature files; document pointers and signed metadata commit together. Storage, renderer and database failures retain the original record/files and clean newly created paths. Invalid images, stale checksums and already-signed records are rejected. Client replacement/deletion endpoints cannot overwrite issued agreements. Eligible pre-signing case stages advance without adding unsolicited notices; later case stages are retained.

Verification uses synthetic records, fake mail, real PNG/PDF persistence and page comparisons, failure injection, client/staff-preview/privacy boundaries, public/portal upload integrity, actual draw/checkbox/submit/retry interactions, and Education/standalone signing regressions. Independent testing, separate review, required exact-head CI and deployed read-only verification precede Done. Never sign a real client agreement as a test.
