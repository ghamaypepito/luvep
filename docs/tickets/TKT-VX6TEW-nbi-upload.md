# TKT-VX6TEW — client Police/NBI PDF uploads

The ticket's original title alone did not identify an implementation. The working scope announced during the Immigration audit uses existing Police/NBI slots: SMCRV and SMCRV1 `police_clearance`, PRSWV `police_nbi_clearance`, and AEWV `police_certificate` (including the existing WORK_AEWV seed alias). No new requirement, visa group, expiry decision or readability/eligibility assessment is added.

The responsible case-checklist resolver determines whether the actual slot or configured alias is in this scope. Authenticated checklist uploads and replacements require both PDF content detection and a `.pdf` filename, retaining the existing50 MB cap. The public upload/replace paths use the same scoped rule without changing their existing unrelated rules or Immigration authentication boundary. Invalid files are rejected before storage or existing-document changes; accepted replacements enter Submitted review, never automatic approval. Existing historical images remain accessible through the normal owner/staff routes.

Requested-document records have no typed checklist binding. Only an existing document for the same case/request can establish the slot; client-supplied keys or an NBI-like label cannot select the policy. Bound scoped requests receive the same validation and PDF UI hints. A single established scoped binding carries to the next uploaded document. New unbound requests remain under the generic document rule; staff should use the existing checklist upload slot for Police/NBI clearance. Ambiguous request history does not invent a slot, but any actual scoped binding still requires PDF. No label migration or global file policy is introduced.

Actual client checklist/request controls and tracker replacement modal show PDF-only accepts/hints when the server resolves this policy. The tracker upload modal already restricts non-face uploads to PDF. Generic requests and unrelated checklist items retain their existing controls. No real records, uploads, approval states, notifications or ticket statuses were changed during implementation.

Validation: synthetic actual-byte PDF/PNG tests cover all four production codes plus the seed alias, disguised images, aliases, unrelated/missing slots, request binding, old-file preservation on rejected replacement, owner/privacy and Submitted status. Existing Track, request/RFI, checklist, MIME, automation and MediaDrive upload-name regressions must pass. Actual React component coverage is `tests/Frontend/nbi-client-pdf.cjs`, registered in CI. Independent testing, separate review, CI and deployed verification are required before closure.
