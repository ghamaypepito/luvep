# JMC legacy event-contact consent repair

The 6 November 2026 JMC event used a required event-contact agreement before separate optional follow-up/newsletter choices were introduced on 8 November. The added boolean defaulted pre-existing records to false, hiding that original agreement from the school-mail audience. The live cohort contains 127 RSVP addresses and three programme-only addresses; 33 addresses also have differing names across source records.

Migration `2026_11_18_140000_restore_jmc_event_follow_up_consent` records a separate nullable `legacy_event_follow_up` permission for the Jose Maria College Foundation, Inc. school event on 6 November at 08:30 Asia/Manila. Records must have both registration and original consent before 8 November at 00:00 Philippine time. Cancelled RSVPs, later audited withdrawals and subsequently corrected identities are excluded. Candidate records are locked before audit evidence is read, matching the staff editor’s lock order. Original consent timestamps, submission fingerprints, optional study-tip/adviser and newsletter preferences, verification and applicant links are preserved. The legacy flag is used only by the school-visit follow-up audience; it does not preselect optional email subscriptions. Staff can withdraw that event permission in Edit answers. An explicit event-specific No overrides broader follow-up choices. Identity corrections remove legacy applicability, so the previous identity’s agreement cannot be reactivated through the editor.

Each changed table/visit has an `education.jmc.legacy_follow_up_restored` activity record listing the affected record IDs, original agreement source and before/after permission. No mailing, outreach receipt, subscription, or job is created. Existing unsubscribe, bounce, address/identity and conflicting-source checks still apply.

The migration is idempotent. Application rollback retains the nullable mapping columns and their audited choices so an explicit withdrawal cannot become indistinguishable from an unmapped record; old application code ignores these columns. Original consent and optional choices remain unchanged. Reapplying the repair checks later recorded withdrawals again; it does not reinstate permission after an audited opt-out.

School Mail now shows the individual RSVP/programme names behind an identity exclusion so staff can review the actual evidence. Displaying those names does not change identity matching or create applicant links.
