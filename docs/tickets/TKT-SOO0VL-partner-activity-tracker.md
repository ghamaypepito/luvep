# TKT-SOO0VL — Agent & Affiliate Partner Activity Tracker

## Existing capability and gap
The Affiliate Partners directory already supplies canonical partner User IDs, original-referral attribution, performance reporting, versioned private agreement PDFs and agreement create/update/send/signature audit events. Existing MessageLog and LeadTask records supply mail delivery and client follow-up facts. A unified activity/training/deadline/report workspace was absent. This addition reuses those sources; it does not create a parallel agency registry, signing system or task engine.

## Prepared workspace
Entry: Education > Partner Activity Tracker; also linked from the existing Admin Affiliate Partners directory. Active ordinary Education/Admin sessions need the existing `agents` module permission. No grant is automatically applied. Agents, sub-agents, external clients, unrelated department roles and view-as sessions cannot use this workspace.

- Email: sent date, partner, subject, purpose, responsible staff, Awaiting Response / Responded / No Response and follow-up date. New partner-specific Compose uses an explicitly selected partner ID and fixed single recipient, and lists actual Sent transport records (including a later bounce). Queued/failed mail is not claimed as sent. Reply status is confirmed by staff. Earlier raw-address mail is not associated by matching names/emails; record external/historical work deliberately. Normal Compose defaults remain intact.
- Agreements: portal versions, actual generated/sent/signature events and private current-version PDF access are read through existing records. Metadata can add responsible staff, deadline, remarks and an internal Under Review/Updated tracking state; it cannot change original signature status or issued contract dates. External agreement records support Draft, Sent, Under Review, Signed, Updated, Expired, sent/received/expiry dates and remarks. Current cards use the latest issued portal version, not a newer draft or an older version isolated by a staff filter. Superseded versions remain in history but do not create false overdue alerts.
- Training: partner, topic/date, facilitator, attendance, Scheduled/Completed/Pending and feedback. Completing training updates the same audited record without a second data-entry step. Trained-agent counts require Completed AND Attended and count each partner once in the period; absent/unrecorded attendance is not inferred as trained.
- Client follow-ups: client name, canonical referring partner, date/method/purpose/outcome, application status, next action/date and responsible staff. The existing-client name picker and linked records obey LeadAccess and original-affiliate attribution; an agency/partner grant cannot expose unrelated case records. An optional prospective-client entry can be recorded without linking a portal record. A verified linked client's name comes from the actual record, and an established client link cannot be silently retargeted or removed. Existing follow-up tasks are read automatically only within the actor's existing task department/creator/primary-or-secondary-assignment scope as well as LeadAccess; their completion, assignment and due dates remain controlled by the existing Task Board. Additional next-action notes can be tracked without rewriting the task.
- Private attachments: upload/view/download signed external agreements and supporting documents. Files remain on private storage with access rechecked on each download, a 10 MB per-file / ten-files per-record limit, MIME validation and cleanup if the database/audit write fails. No deletion or silent source-PDF replacement is introduced.
- Dashboard: registered partners, agreements awaiting signature, signed agreements, renewal window, recorded trained partners, pending training, completed/pending/overdue follow-ups. Renewal window defaults to 30 days and can be changed from 1–365. Counts distinguish current workload from dated completed activity. Current application status on automatic tasks is labelled current, not a historical snapshot.
- Reporting: partner/category/staff and inclusive activity-date filters; Monday-based current week, current month and custom dates in the displayed application timezone. Pending/overdue workload and current agreements are not hidden by an old activity's creation date. Excel is a real XLSX with Summary, Activities, Agreements and Overdue workload sheets, filter context, frozen headers and safe string cells. PDF uses the same scoped data and definitions. Exports are bounded to 5,000 combined rows for Excel / 500 for PDF, with a request to narrow filters rather than silent truncation.

## Safety and rollout
Two new tables: `partner_activity_records` and `partner_activity_files`. No columns added to leads/users or changes to partner account roles, commissions, agreement signatures, source task completion or Finance. Source-key uniqueness, same-partner serialization, stale versions, immutable partner/category/client links and transactional actor audit protect saves. Reads do not create activity records or send email. Rollback retains history/files; reapplying the migration is idempotent. Before migration, existing source reads work and new storage actions are withheld.

Approval/deployment still requires the additive migration, deliberate existing-module access for the intended staff if not already granted, a fake/test email delivery check with the existing mail worker, and Emma's live acceptance. No production grants, client records, signatures, real emails or historical bulk imports were changed during investigation. Unrecorded external work and earlier ambiguous raw-address emails cannot be presented as verified automatic history.
