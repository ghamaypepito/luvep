# Luvep HR Release 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver private personnel documents, versioned policy acknowledgements and private HR support requests.
**Architecture:** Extend Release 1 enrollment, access, audit and notification services. All files use private storage and authenticated streaming; responses serialize only authorized fields.
**Tech Stack:** PHP 8.3, Laravel 12, React 19, Inertia 2, existing private filesystem and queue infrastructure.
**Spec:** [Approved design](../specs/2026-10-19-hr-portal-design.md)

## Global Constraints

- All [master-plan constraints](2026-10-19-hr-implementation.md) and notification rules apply.
- Employees see their own authorized records; confidential files default private. Admin employee preview is read-only and audited.
- Employee ownership alone does not unlock HR-private or restricted personnel documents.
- No confidential payloads, storage paths or private notes in shared Inertia props, email, analytics or general audit metadata.

## Review Focus

- Old version URLs after release revocation must stop working: task 1.
- Uploaded HTML/SVG or spoofed extensions must not execute in the application origin: task 1.
- Policy publication racing with acknowledgement must preserve the exact acknowledged version: task 2.
- Reassigning a private case must revoke the former reviewer's case access: task 3.
- Admin preview, list counts and search must not reveal employee-invisible records: tasks 1–3.

**Interfaces:** `DocumentService::upload(User $actor, HrEmployee $employee, UploadedFile $file, array $metadata): HrDocumentVersion`; `release(User $actor, HrDocumentVersion $version, bool $released): void`; `download(User $actor, HrEmployee $subject, HrDocumentVersion $version, bool $preview): StreamedResponse`. Use original actor for authorization and employee scope for preview.

- [ ] Write failing tests for owner release, unrelated employee, revoked release, archived target, old version and preview. Pin `test_employee_cannot_download_unreleased_version`: `$this->actingAs($employee)->get($url)->assertNotFound();`. Assert list counts also exclude that version.
- [ ] Add upload tests for valid PDF/PNG/JPEG, empty or over-10-MiB content, extension/MIME mismatch and HTML/SVG rejection. Verify private storage, attachment disposition, `nosniff` and private/no-store responses; audit actor/version IDs without content.
- [ ] Run `php artisan test tests/Feature/Hr/HrDocumentsTest.php`; confirm expected failures.
- [ ] Implement immutable versions with private random storage keys, original display filename, detected MIME, hash, creator and timestamp. Classification values: `employee_shared|hr_private|medical|compensation|case`; default `hr_private`. Require class-specific grants. Release only an explicit version, never automatically release future versions. Employee self-service downloads require both ownership and an explicit release; restricted classes additionally require the appropriate release authority. Preview cannot exceed either the actor's permission or employee-visible scope. Archive keeps history and denies further self-service access.
- [ ] Build employee own-files and scoped HR upload/version/classify/release views with server validation and empty/error states. A safe file metadata response contains no storage keys. Rerun tests, build assets, then commit `feat(hr): add private versioned personnel documents`.
