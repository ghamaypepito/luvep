# Live Ep Admin overview

Implements the existing approved local Admin concept with real foundation data. Continue the established Luvep layout, green palette, direct execution and admins-only pilot. No new generation, connector credentials, paid activation or operational writes are authorized.

Use `/admin/ep-agent` with Overview, Tasks, Usage & budgets and API Connectors hash tabs; `#connectors` is a real deep link. Put Ep Admin beside Ep Agent/Manager in the admin sidebar. Show actual run metadata, current usage ledger and budget accounts, without conversation ids, titles, prompt/message bodies, private drafts, idempotency keys, system instructions or secrets. Detail dialogs are metadata-only. No links expose another user's private chat.

Summary uses a server-defined UTC creation window (this month, seven days or thirty days). Task portal/status filters affect the task table only; ledger totals are labeled all-portal data. Recorded charges are reconciled ledger amounts, not provider invoices. Outstanding holds span all dates so old uncertain charges do not disappear. Missing per-run usage/cost stays null. Budgets show each account's own period/currency, balances, freeze/expiry status and safe remaining allowance; no assumed monthly dollar limit. Multiple accounts are never added into a fictional shared cap. Unattributed ledger entries are explicitly reported.

Connector tab says Ep generation is not connected/off. Super Admins may see only safe existing Claude configuration status/model and the existing settings link. Plain admins cannot see restricted connector status or change credentials. No embedded duplicate key form or test button. Existing Claude connector configuration does not imply Ep transport is connected. Knowledge, Employment/Residency and action capabilities are labeled unavailable rather than populated with sample data.

Read-only SQL APIs enforce fresh admin identity, pilot access and user-view denial. Responses use allowlists and no-store. Filter changes/refreshes replace data, close details and cancel stale requests. Errors/revocation clear content. Native dialogs restore focus. Desktop/mobile layouts inherit portal chrome; no public contact overlays or floating chat obscure controls.

Scope chosen: extend the actual foundation and existing connector page. Retaining a demo would not deliver live data; duplicating connector/settings storage would create inconsistent configuration. This is a live monitoring interface, not a task dispatcher, budget editor or provider integration.
