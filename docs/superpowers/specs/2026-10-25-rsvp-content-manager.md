# RSVP content manager and shared event schedules

The user requests an easy Education backend to replace the RSVP page's images/text, organized professionally from top to bottom, plus Add schedule. They confirmed one shared page across schools. They also require newly added schedules to appear in the programme-registration school/event dropdowns.

## UI and editing
Preserve EP branding and automatic appearance. Reorganize the existing protected manager into Page content → Schools & schedules → Attendance → Delivery, with anchor navigation, consistent controls, current image previews, clear save/publish feedback and responsive layouts. Content sections follow the public page: Event page (photo/title/intro), New Zealand panel (photo/caption), RSVP form (photo/title/intro), Confirmation (photo/title/message), Helpful information (FAQ and footer). Text is plain escaped content; image upload only, no HTML/URL editing. A save publishes that section. Keep current defaults when nothing is configured, other sections unchanged, and existing image when no replacement is chosen. Content changes must not queue attendee notices. Contact consent, verification and account/pipeline explanations remain system-controlled.

Use the existing app_settings JSON storage per content section, no CMS tables. Images use the public disk, PNG/JPG/WebP, max5MB/max6000px; one photo per save avoids oversized batch requests. Preserve old media for rollback; remove a new upload if its database write fails. Education/admin authorization, CSRF and audit apply.

Schools & schedules contains Add schedule, accepting an existing or new school, event title, city, format, optional date/time, timezone, location and explicit confirmed/open state. Several schedules may belong to one school. Create a unique slug, inherit an existing school logo when appropriate, and never change older visits. Existing schedule editors include school/event metadata and logo control together with dates. A logo upload affects its selected visit, consistent with current behavior. Date/time/location/format/city confirmation/cancellation changes revise schedules; ordinary page text/photo edits do not. Existing attendance and encrypted/admin-only Slack controls remain functional.

## Programme registration
Use EducationVisit as the single event catalogue. The school dropdown lists schools with noncancelled schedules, including closed RSVP intake so past attendees can still apply. A second dropdown lists that school's schedules. Managed event details are displayed from the catalogue and authoritative on the server; do not trust posted school/name/date/time for a selected visit. Other school/event remains an explicit legacy manual option. New/edited visits reflect on fresh RSVP/registration page loads. Default origin country remains Philippines.

Add nullable education_visit_id FK to education_event_registrations and allow nullable event_date/time for a selected TBC visit. Legacy manual submissions retain required date/time validation. Model summaries render honest TBC values. Snapshots retain the selected event's details at submission; FK retains the relationship. No invented dates. Keep UUID idempotency, owner Emma, both recipients, returning ownership/stage, verified RSVP matching and Slack behavior. Managed replay fingerprints use normalized client identity and visit ID, not mutable catalogue fields, and prior UUIDs are checked before resolving current schedule state. Selected schedules marked matched; legacy manual events remain pending.
