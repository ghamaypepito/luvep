# Approved Luvep Media Drive

User approved the interactive Media Drive on 2026-11-05, after choosing invited-email verification. Visual reference: ../media-drive-preview/README.md and app.jsx. Preserve existing client-profile layouts; add the attachment picker rather than replace the profile.

## Deliverable
A private client file library available from every staff portal, with client folders and subfolders, list/grid/search, multiple uploads, file preview/download and activity. A share includes the selected folder, its descendants and future uploads; new children inherit that shared access. Staff can share a folder with an invited email as Viewer or Editor, copy its link, change expiry/access or revoke it. Viewer can view/download; Editor can additionally upload, without deleting files or changing sharing. The link requires an email verification code before showing files. Client uploads remain awaiting review.

The Media Drive/Upload picker is added to shared lead-profile document uploads and internal-note attachments, immigration case checklists and accommodation tenant documents. The picker stays scoped to its client. Attached files reference the same MediaFile identity; bytes are not duplicated and existing review decisions are not reset. Standalone tenants are supported as well as leads. Existing files and existing upload routes remain functional; historical files are not automatically moved or exposed to shared folders.

## Architecture (implementation choices)
Use the existing Laravel/Inertia/React app and private storage rather than add Google Drive or another paid service. MediaFolder roots belong to one Lead or Tenant; child folders have immutable parent/root and materialized numeric ancestry. MediaFile owns immutable private bytes and records its uploader and initial review state. LeadDocument/TenantDocument can reference a MediaFile. Attaching again to the same target is idempotent; repeat references to the same target retain its current review state; a new target starts Submitted; removing/replacing a document reference preserves Drive bytes. Folder files are not automatically added to legacy client trackers.

Record visibility follows existing department pipelines/registers/case access and explicit portal grants. Recruiting accounts are restricted to their referrals and cannot manage external sharing. Finance can use clients already in its invoice/case-financial/assigned-task workflow. Tenant folders are for Admin/Accommodation. Employee HR documents never enter the client library. Authenticated clients get their own invited links, then must verify the invited email.

Sharing uses high-entropy revocable links, encrypted token plus lookup hash, normalized invited email, Viewer/Editor, expiry (default 30 days) and versioned access. Verification codes expire after 10 minutes, are hashed and session-bound, allow five attempts, and are replaced on resend. Resend cooldown is 60 seconds, maximum three emails per share/hour plus IP throttles. Verified access expires after one hour and is rechecked on every list/preview/download/upload; revocation, permission/email changes and expiry invalidate it immediately. No unverified file names, client details, internal notes or review identities are serialized.

Uploads accept the preview's PDF, JPEG/PNG/WebP, Office, CSV/text and MP4/MOV/WebM formats, 100 MiB each, up to ten selected. Browser queues individual requests with progress and a retry key to avoid duplicate assets. Server verifies content/type/size and stores random paths outside public storage. Preview uses a MIME allow-list, nosniff/no-store headers and safe filenames; unsupported inline formats download. All access and sharing/upload/attachment changes have staff/client-aware audit events.

## Validation and rollout
Additive migrations only. Meaningful backend authorization and OTP tests plus frontend interaction tests, full CI, independent code review, production migration/deployment and live browser checks. Verify production request-size limits for 100 MiB files. Use synthetic data in isolated tests; do not send invitations to real clients or mutate real client documents for verification. The existing localhost prototype remains available during implementation.
